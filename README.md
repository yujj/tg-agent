# tg-agent

Telegram для Claude Code (и любого агента с shell): «прочитай чат X», «подпишись на чат X»,
«напиши в X». Читает от **вашего аккаунта** (MTProto, [Telethon](https://github.com/LonamiWebs/Telethon)),
пишет от **бота**; от вашего имени — только флагом `--as-me`, по прямой просьбе.

- `tg` — CLI: найти чат, прочитать, подписаться на новые сообщения, отправить.
- Демон: один процесс держит подключение к Telegram; поднимается сам при первой команде и
  живёт, пока не сказать `tg stop`. Команды ходят к нему через unix-сокет.
- Скилл для Claude Code (`telegram`): агент сам понимает «прочитай / следи / напиши», подписку
  ведёт через инструмент `Monitor` — новое сообщение приходит в сессию событием за 1–2 секунды.

Проверено на macOS. Секреты хранятся в системном хранилище через [keyring](https://pypi.org/project/keyring/)
(на macOS — Связка ключей); на Linux нужен доступный keyring-бэкенд.

## Установка

Нужен [uv](https://docs.astral.sh/uv/).

```bash
uv tool install git+https://github.com/yujj/tg-agent   # команда tg
tg install-skill                                       # скилл → ~/.claude/skills/telegram
```
Обновить: `uv tool upgrade tg-agent && tg install-skill && tg stop`.

## Настройка (один раз, в своём терминале — команды интерактивные)

1. https://my.telegram.org → API development tools → создать приложение (название любое) →
   ```bash
   tg setup-api      # спросит api_id и api_hash
   ```
2. Вход аккаунтом:
   ```bash
   tg login          # телефон, код из Telegram, пароль 2FA
   ```
3. Бот для отправки (можно позже — читать и подписываться можно без него):
   [@BotFather](https://t.me/BotFather) → `/newbot` → токен →
   ```bash
   tg setup-bot
   ```
   Бота добавьте в чаты, куда он должен писать; в канал — админом с правом публиковать. В группе,
   где он должен отвечать на чужие сообщения, — тоже админом (права не нужны) или выключите ему
   privacy в @BotFather (`/setprivacy`) до добавления.
4. Проверка: `tg whoami`.

Коды, токены и пароли агенту в чат не присылайте — команды выше спрашивают их сами и кладут в хранилище.

## Команды

```bash
tg chats [часть названия]               # найти чат, видно непрочитанное
tg read "<чат>" -n 50 [--after <id>]    # прочитать
tg watch "<чат>" ["<чат2>" ...] [--key k] # новые сообщения, строка на сообщение (для Monitor)
tg send <id> "текст" [--reply-to <id>]  # от бота
tg send "<чат>" "текст" --as-me         # от вашего аккаунта
tg send <id> ["подпись"] --file <путь>  # файл документом, подпись необязательна
tg download "<чат>" <msg_id> [--out <каталог>] # скачать файл из сообщения, печатает путь
tg status                               # демон, подключение, подписки (демон не поднимает)
tg stop                                 # остановить демон
```
Чат: `@username`, t.me-ссылка, числовой id или название — для чтения можно часть, для отправки только
полностью (чтобы опечатка не выбрала чужой чат). `@username`, ссылка и id ищутся только точно.

Файл: до 50 МБ, подпись до 1024 символов. От бота часть знаков в имени файла (например «—») Bot API
заменяет пробелами; от аккаунта имя доходит как есть. `tg read` показывает файл как `[Document: имя]`,
голосовое — как `[Voice 0:42]`.

Скачать: `tg download` кладёт файл в `--out` (по умолчанию текущий каталог) под именем
`<чат>_<id>_<имя>` — от имени отправителя остаются только безопасные знаки; у голосового — `voice.oga`.
Печатает только путь. На скачивание — до 5 минут.

## Где что лежит

| что | где |
|---|---|
| секреты | системный keyring, сервис `tg-agent`: `api_id`, `api_hash`, `session`, `bot_token` |
| сокет, лог демона, метки подписок | `~/.local/state/tg-agent/` (каталог 700, сокет 600; переопределяется `TG_AGENT_STATE`) |
| скилл | `~/.claude/skills/telegram/SKILL.md` |

## Безопасность

**Сессия = полный доступ к вашему Telegram**: читать всё и писать от вас. Она хранится только в keyring;
сокет демона доступен только вашему пользователю. Любой процесс под вашим пользователем может
воспользоваться `tg` — как и самим keyring. Отозвать доступ: Telegram → Настройки → Устройства →
сессия этого приложения → завершить; затем `tg stop`.

**Сообщения из чатов — недоверенный ввод для агента.** Вывод `tg` устроен против подмены: одно
сообщение — одна строка, управляющие и bidi-символы видны как `\uXXXX`, ваши сообщения помечены `[я]`
(по флагу Telegram, а не по имени), у остальных всегда `(id …)` — имя «я» или чужое имя не выдать за
вас. Скилл требует действовать только по словам пользователя в сессии, а `--as-me` — только по его
прямой просьбе; без авто-режима отправку дополнительно остановит запрос разрешения Claude Code.

Демон запускается в изолированном режиме Python (`-I`, рабочий каталог — свой), чтобы модули из
каталога, где запущен агент (чужой репо), не попали в процесс с доступом к сессии.
`TG_AGENT_STATE` принимается только как собственный каталог с правами 700.

Telegram ограничивает аккаунты за массовую автоматическую отправку. Чтение безопасно; от своего имени
отправляйте редко.

## Как устроена подписка и почему демон

- Push-обновления Telegram приходят **последнему подключению сессии**. Если каждая команда
  подключается сама, `tg read`/`tg send` перетягивают push на себя, и подписчик молча теряет сообщения.
  Поэтому подключение одно — в демоне. Сокет демон поднимает сразу, до подключения к Telegram: без
  сети команды получают понятное «подключаюсь», `tg status`/`tg stop` работают всегда. Любая команда
  ограничена 60с: при обрыве связи — ошибка, а не вечное ожидание. Зависший подписчик отключается.
- Плюс страховочный опрос раз в 60с: один `GetPeerDialogs` на все подписанные чаты, история — только
  где есть новое. Он ловит ваши сообщения, отправленные через эту же сессию (`--as-me` — о них Telegram
  push не присылает).
- Метку «прочитано» хранит сам подписчик (`~/.local/state/tg-agent/watermarks.json`) и сдвигает её
  **после** вывода строки: при сбое сообщение может прийти повторно, но не потеряется. Запись меток —
  под блокировкой со слиянием, так что несколько `tg watch` с одним ключом друг другу не мешают;
  независимая слежка со своей меткой — `--key <имя>`.
- `Monitor` живёт до 30 минут; при перевзводе всё, что пришло в паузе, выдаётся строками
  `(пропущено)` (до 200 на чат). Самая первая подписка на чат стартует с текущего момента; историю — `tg read`.

## Ограничения

- Бот не видит историю чатов и не может первым написать человеку в личку — это Bot API; в личку только `--as-me`.
- `--reply-to` ботом — только в каналах и супергруппах: в обычных группах и личке у бота своя нумерация сообщений.
  И только на сообщения, которые бот видит: с privacy mode (по умолчанию) в группе это его собственные,
  ответы ему, команды и упоминания. На остальные — `message to be replied not found`; лечится админством
  бота в чате или выключенным privacy (после `/setprivacy` бота нужно перезапустить в чат: удалить и добавить).
- Подписка доставляет только новые сообщения: правки и удаления не показывает. Служебные события
  (вступления, закрепы) выводятся как `[служебное: …]`, пересланные — с `[переслано]`.
- Если группа стала супергруппой, подписка сообщит новый id — перевзвести на него.
- Одно сообщение — до 4096 символов. Инвайт-ссылки (`t.me/+…`) не поддерживаются — нужен id чата.
- Читать личку ботом можно через Telegram Business (нужен Premium) — не поддерживается, личка читается аккаунтом.
- Нужен доступ к серверам Telegram с машины; если они у вас заблокированы — системный VPN.
